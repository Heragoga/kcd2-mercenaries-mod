FOR NEXT UPDATE:
- added 4 combat stances, set by talking to a mercenary, apply while idle too: attack everyone, only attack whoever you attack, only defend themselves, fully passive
- mercs now spread out across targets instead of dogpiling one enemy (anti-swarm cap tracked via O(1) lookup instead of O(mercs) position scan)
- badly wounded mercs disengage instead of fighting to the death
- perf: cut per-merc combat scan cost - "everyone"/"player_target" stances skip the expensive per-candidate engine GetTarget calls entirely, "defend" caps candidates checked to the nearest 8
- added new "Skalitz" equipment preset (new item set); the old preset labeled "Skalitz" is now correctly labeled "Leipa"
- major perf pass: "is player mounted" and "merc fell too far behind" checks used to run per-merc, every ~0.5-5s each, via engine StanceCheck nodes and duplicated 10-ray physics sweeps; both are now single checks done once/sec for the whole squad. Also cut the emergency-teleport BT node entirely, skip the enemy scan and squad loops outright when you have no mercs, and stretched a few of the busiest per-merc ticks (follow-stuck detection, leash distance) to lower frequencies
- fixed following/horse bugs: the "is CrimeFollower stuck" check compared the merc's own GetVelocity() against the player's every ~1s and, if it looked too slow for too long, tore down and reissued the entire mercenary_follow behavior tree. That read near-zero constantly for harmless reasons (riding a horse, just starting to move, turning onto a new path segment) and kept restarting follow before a merc ever built up real speed - the "mercs stand around and twitch" bug - and also wiped horse state on every restart, causing the "mercs constantly spawn new horses" bug. Removed the check entirely (bodyguards' equivalent companion_scheduler has no such check and follows fine - CrimeFollower recovers its own pathing without help). Horse lifecycle now also survives a follow-behavior restart by adopting an already-existing horse instead of deleting and respawning it
- reverted the "Recall Mercenaries" screen prompt and the idle gestures/night torches/gossip banter additions - the prompt never worked, and the extra behaviors made the twitching bug above worse
- temporarily removed archer/crossbow/handcannon from the weapon loadout dialogue (ranged combat AI needs more work first); the underlying preset data is untouched so they can be re-enabled later
- localization added for 8 more languages: Italian, Korean, Traditional Chinese, Polish, Portuguese, Spanish, Ukrainian, Vietnamese (16 total now)
- fixed mercenary horse assignment always picking the same horse for every merc: a debug line was overwriting the deterministic per-merc hash pick, and the hash math itself had a precision bug that made similarly-named mercs collide onto the same horse - both fixed
- added Kite Shield and Skalitz Wave Shield (from House of Kobyla Arms, Armour and Regalia) as new sword-and-shield loadout variants, weak/medium/strong (bringing sword+shield up to 4 variants per tier like the other shield weapon types), and added no-waffenrock hood-forward outfit variants to the Skalitz preset for all three tiers, using the new Plain Red Skalitz Hood for medium/strong tiers
- added a debug console command, merc_spawn_battle, that spawns a 20-merc line facing a 20-bandit line for combat testing, player centered in the merc line
- added "Renegades": a brand new hostile-to-everyone NPC type (own brain, own souls, own faction) for combat testing. They wear whatever mercenary outfit/weapon preset you hand them at spawn time. Console: merc_spawn_renegade (or _weak/_medium/_strong), or merc_lua mercenaries:SpawnRenegade(amount, outfitPreset, tier, weaponPreset) for full control
- added an in-game dialogue option ("Arrange a skirmish") to spawn renegades without touching the console: talk to a mercenary, pick a tier (rabble / seasoned / veteran), then a headcount (1/3/5/10/20). They spawn wearing whatever outfit/weapon preset the squad currently has equipped
- fixed renegades just standing around instead of fighting: assumed the plain vanilla switch subbrain would be enough for "attack anything hostile" since it's purely faction-driven, but that's wrong - proactive combat needs an active switch that fires crime/attack interrupts itself (same as mercenaries' own switch does), the vanilla one only reacts once something else starts a fight. Gave renegades their own minimal switch + attack behavior tree (renegade_scheduler.xml, renegade_attack.xml) that scans for the nearest player/merc every second and attacks
- fixed the renegade dialogue not spawning anything at all: the three new dialogue tokens were referenced in the quest files and Lua but never actually declared as items in item__mercenaries.xml, so CreatePlayerReward had nothing to grant and the count-detection in MonitorInventory never saw anything to act on
- renegades spawned via dialogue no longer stack on top of each other (was doing a fresh safe-position raycast per unit, which returns nearly the same spot every time since the player hasn't moved between spawns - now finds one safe spot and fans the group out from there)
- renegades now attack indiscriminately - any living NPC or the player within 50m, no faction filtering at all - with an anti-swarm cap of 2 renegades per target; only piles more onto an already-claimed target once nothing else is in range
- fixed renegade_attack interrupt not being found ("Behavior renegade_attack requested by interrupt was not available"): matching the shared "so_interrupt" brain id mercenaries use wasn't enough on its own - a second, separate SmartEntity file with the same registry name apparently doesn't merge with an existing one, so the renegade entry never actually got registered. Folded renegade_attack directly into the existing mercenaries SmartEntity file as a second behavior template alongside mercenary_attack/mercenary_follow instead of maintaining a separate file
- fixed a spam of engine errors on every mercenary horse tick ("Can't set data variable 'despawnCountdown'", "horse ... Expected Pointer, got nil"): despawnCountdown was being written from Lua without ever being declared as a real behaviour-tree variable, and both it and horse were being cleared with Lua nil, which the engine's typed variables reject outright. Declared despawnCountdown properly and stopped nulling both from Lua - horse only gets read while horseSpawned is true anyway, so leaving a stale value between horses is harmless, and despawnCountdown just resets to its default instead
- renegades now stick with their current target instead of re-rolling it every ~1s tick, as long as it's still alive and within 5m - only rescans for a fresh target once it dies, despawns, or wanders further than that
- fixed renegades twitching in place and only actually fighting when hit at point-blank range: the switch was re-firing the attack interrupt every 500ms even while already mid-fight, tearing the attack behaviour tree down and restarting it before it ever got the chance to close distance and land a swing (only worked at melee range because the restart was fast enough there to still land a hit, plus the player's own hit independently triggers the target's vanilla "someone's attacking me" reflex). There was also a stray "$currentTarget = null" firing every tick right before the target search, which wiped out last turn's sticky-target fix before it ever ran. Both removed - the switch now only (re)issues the attack interrupt when not already in the crime_interruptAttack context, same as the real mercs' own scheduler does
- renegades no longer default to wearing the same outfit as your mercs - added a lookup (mercenaries.RenegadeOutfitOverride / GetRenegadeOutfitFor) that always picks a visually distinct preset instead, used by both the dialogue and merc_spawn_battle
- merc_spawn_battle is now fully customizable: separate weak/medium/strong headcounts and separate outfit/weapon presets per side (merc_lua mercenaries:SpawnTestBattle({weak,medium,strong}, mercOutfit, mercWeapon, {weak,medium,strong}, enemyOutfit, enemyWeapon)), and within each side the stronger tiers now always spawn at the front of the line instead of a random mix. The enemy side is now spawned as renegades instead of raw bandit souls, so it gets the same "attack everyone" AI already built for renegades
- mercs now show a tier title instead of the same generic "Mercenary" name for everyone: weak tier shows "Novice Mercenary", strong tier shows "Veteran Mercenary" (medium tier keeps plain "Mercenary"). Root cause was that every regular merc soul, regardless of tier, pointed at the exact same character/uiName entry - now the weak and strong tiers have their own dedicated character entries and title strings
- confirmed the renegade equipment mapping: "Prague" isn't a real outfit preset, it was a mix-up for Kuttenberg, so Generic-outfitted mercs now face Kuttenberg-dressed renegades as the permanent, intended pairing (not a placeholder)
- added merc_battle, a plain console command version of the battle spawner: merc_battle <mercOutfit> <mercWeapon> <enemyOutfit> <enemyWeapon> <countPerSide>, splits the count evenly across weak/medium/strong. No merc_lua/table syntax needed for the common case
- fixed the renegade line in merc_spawn_battle/merc_battle not actually facing the mercs: their facing angle was just playerAngleZ + pi, which can land outside the engine's expected -pi..pi range depending which way you're facing when you spawn the battle, breaking the flip. Now normalized back into range
