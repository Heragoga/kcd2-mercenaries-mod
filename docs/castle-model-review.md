# Castle model review — updated 11 September 2026

## Open battlements and corrected walkways

Following the user's review, the small shingle canopy has been removed from both
towers. The fighting platform is open, with the stairwell guards retained.
The earlier 7.5/10 judge score describes the previous roofed version; this follow-up
has not received another score, respecting the three-review limit.

The standard curtain's walking strip is centred at local Y=0.10 m; the hand-built
curtain's is centred at Y=0.35 m. Tower placement now uses these individual offsets.
The tall tower's ground door moved from X=1.82 m to X=2.40 m to clear the wider
curtain at courtyard corners. Both doors still enter the same ground chamber.

The corner meshes have been rebuilt as continuous mitred strips. Their old
overlapping wall arms placed inner kerbs across the walking route. The 135-degree
corner now occupies 3 m per arm to give the turn enough room; the others use 2 m.
Straight-wall collision slabs now overlap at tile joins. The hand-built wall's
deck/body end was about 8 cm short of its parapet end: that end and its collision
slab now reach the full tile boundary.

**39,318 mesh samples pass across 11 layouts generated by the real Lua builder:**
both wall heights, squares, a 37-degree rotated square, open ends, right-angle
bends, and all three standard corner types. These check rendered and compiled
collision floors, a 0.54 m walking strip, body/head obstructions, exact tile seams,
tower entrances, and doorway centring. Door centre error is below floating-point
precision at useful scale. These remain static geometric tests, not a live game
movement test. The models were authored and exported through Blender MCP.

The latest evidence is in `assets/blender/workspace/review/open-battlements/`;
the main `castle_reworked.blend` is updated. The historical results below describe
the first three art passes and their more limited tower-only route checks.

To reproduce the follow-up, build with `review_castle.build`, then call
`repair_hand_walk.build(repo, output)` in the same Blender MCP session. Compile
with `assets/compile_castle_review.py <output>` and
`assets/compile_hand_repairs.py <output>`. Generate the exact game layouts with
`tools/export_castle_layouts.py`, then call
`validate_castle_joins.check(repo, report_path)` through Blender MCP.

The rebuilt kit contains three 4 m curtain variants, three corner pieces, and two
enterable towers. The towers replace the old cramped spiral/solid-floor design.
The hand-built wall geometry is preserved; its material headers were repaired.

## Player use

After restarting the game to load the updated mod archive:

```text
merc_castle_wall 1
merc_castle_tower 2
merc_castle_build
```

Wall type 5 uses the existing hand-built curtain and automatically selects the
6 m tower floor. Wall types 1–4 use the 4.9 m tower floor. Build mode defaults to
90-degree snapping for this kit. The standard curtain has separate 45/135-degree
corner pieces; these replace towers at those angles. Custom tower yaw overrides
and uneven terrain can invalidate the tested doorway alignment.

The tower's ground entrance is offset into the courtyard beside the joining wall.
Three 1.70 m wall-walk ports connect to its central hall; the rear face is reserved
for stairs. Stair flights are 1.15 m wide, with return landings, smooth collision
ramps and collidable timber guards. Platforms are at 9.2 m / 10.3 m. The main shaft
is 7.6 m square, with projecting footings and parapet stonework.

## Artwork and review

All modelling/export operations used Blender MCP's addon socket transport in a
dedicated Blender 5.2 session. The original user workspace file was preserved.
The final editable scene, packed with its local preview textures, is
`assets/blender/workspace/castle_reworked.blend`. Its hidden **Castle EXPORT**
collection contains the actual source meshes including collision; **Castle REVIEW**
contains display duplicates. The cutaway is an inspection aid and is never exported.

Game-native stone, paving, wood and shingle textures are referenced by the shipped
materials. The Blender preview approximates the engine's material blending;
lighting, normals and blend masks will differ in KCD2. No game textures or native
prop meshes were added to the mod package. Four native props are spawned separately
and registered for cleanup with their tower.

An independent judge inspected eight views per iteration. Exactly three art
iterations were scored: **6.5 → 7.0 → 7.5 / 10**. The final assessment calls this a
coherent, good mod asset, below KCD2 production parity. Remaining weaknesses are
repeated coping/merlon rhythms, sharp dressed stone, limited repair/material history,
and regular timber/shingle detailing. There was no fourth art iteration.

## Validation and limits

- Both source and compiled towers pass 166 sampled route checks in total: collision
  floors plus upward head-clearance rays at the centre and 0.27 m radial offsets.
  Minimum sampled headroom is 2.397 m; maximum tread/ramp height difference is 0.095 m.
  These are offline geometric checks, not a capsule sweep or live player test.
- Real Lua builder functions pass 20 corner orientations across five rotated square
  layouts, end/disabled tower cases, oblique-corner fallback, tall-tower selection,
  and prop spawning/cleanup registration.
- All eight FBXs compile through KCD2's own `rc.exe`. The compiled files retain UVs,
  variable vertex colour alpha, expected geometry slots and the resolved material
  library. Source and compiled triangle counts differ slightly because RC removes
  degenerate triangles.
- RC compacts unused material slots. The build now remaps its embedded material
  names to the shared seven-slot table, so a wall's trim/proxy cannot shift into the
  wood/trim slots. The old material-path patcher also incorrectly grew a fixed
  128-byte field; it now preserves that field and can repair its earlier outputs.
- Main/tall compiled towers have 83,106 / 85,623 triangles including proxy geometry.
  No LOD chain or large-castle performance benchmark was produced.
- Live KCD2 appearance, movement, physics, NPC navigation and terrain joins have not
  been verified. The judge's score is an artwork assessment, not gameplay certification.

Evidence PNGs and JSON reports are copied to `assets/blender/workspace/review/`.

## Reproduce

With Blender MCP listening on localhost:9876, execute a script calling
`review_castle.build(repo, library, output)` via
`python tools/blender_mcp_client.py --code your_script.py`. The library is the user's
existing `kcd2_blender` directory. The function exports all eight pieces.

```text
python assets/compile_castle_review.py tmp/castle-rework/iteration3
python tools/check_castle_materials.py
python tools/check_castle_placement.py
```

Compilation validation requires NumPy; placement validation requires Lupa's
`luajit21` runtime. `assets/build_castle_kit.ps1` also supports regenerating the eight
meshes with Blender 5.2, including the new material-slot repair step.

The selective installer is `tools/install_castle_assets.py`: prepare a verified
archive from the installed mod, then install it only if the original hash is still
unchanged. It preserves every other archive entry and records the backup and hashes
under `tmp/castle-rework/install/install.json`.
