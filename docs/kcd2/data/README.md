# docs/kcd2/data/

Machine-generated tables. Do not hand-edit; regenerate with the script named in each
section below. Every generator is stdlib-only Python 3, run from the repo root.

## cvars.tsv

One row per console variable or command recovered from the retail binary
(`E:\kcd2_disasm`, build `release_1_5_1308617_856`), generated by `tools/gen_cvar_reference.py`.

```
python tools/gen_cvar_reference.py
```

Regenerate after `E:\kcd2_disasm` is rebuilt for a new game patch (see
`E:\kcd2_disasm\AGENTS.md`), or after `data/` (this mod's Lua) or
`references/kcd2-mod-docs-main/Scripts/` (vanilla Lua) change enough to be worth
re-scanning.

### Columns

| Column | Meaning |
|---|---|
| `name` | The cvar/command name, exactly as it appears in the binary's string table. |
| `kind` | `cvar`, `command`, or `unknown` (see Method and Confidence below). |
| `prefix_group` | Everything before the first `_`, lowercased (`wh`, `ac`, `ai`, `g`, `r`, `e`, `p`, `sys`, `cl`, `s`, `ca`, `mfx`, ...). A rough subsystem grouping, not authoritative -- see `console-variables.md` for what each prefix actually means. |
| `default` | Default value, when a literal immediate could be recovered from the registration call-site. Often blank -- many defaults are computed at runtime (from another cvar, a config value, a platform check, ...) rather than being a compile-time constant, and are not recoverable this way. |
| `help` | The one-line help/description string passed to the registration call, when one could be matched to the right call-site. |
| `registered_in` | Name (or `sub_<RVA>` if unnamed) of the function(s) that reference this cvar's name string in the binary. Usually one bulk "register everything for subsystem X" function; occasionally several (rare duplicate registration, or a mix of registration + a `GetCVar` read elsewhere). **Not stable across game builds** -- `sub_` names are RVA-derived and shift on every patch; re-run this generator after a rebuild rather than trusting a saved RVA. |
| `notes_doc` | Repo doc(s) under `docs/` (this generator's own output excluded) that mention this cvar by name, semicolon-separated. |
| `vanilla_script_uses` | Number of files under `references/kcd2-mod-docs-main/Scripts/` (vanilla game Lua) whose text contains this name. |
| `mod_uses` | Number of files under `data/` (this mod's own Lua) whose text contains this name. |
| `confidence` | How `kind`/`default`/`help` were obtained -- see below. |
| `source` | `corpus` for names that came from the disasm corpus's own `cvars` table, or a `harvested (...)` note for names recovered by this generator's own second pass (see "Known gaps" below) -- the corpus's extraction turns out to miss every cvar whose name starts uppercase. |

### Confidence values

| Value | Meaning |
|---|---|
| `high` | The registration call went straight to one of a handful of known, hand-verified IConsole wrapper stub functions (see the script's module docstring) — the caller-vs-`GetCVar`-reader ambiguity does not apply. |
| `medium` | The registration was recognised by vtable slot offset (e.g. an inlined `call qword ptr [rax + 0x108]` for `AddCommand`) rather than a named wrapper, or `kind` is right but `default`/`help` extraction is best-effort pattern matching that can occasionally grab an unrelated adjacent string or miss a runtime-computed default. |
| `low` | No registration call-site could be tied to this name at all (`kind` left as `unknown`). This does **not** mean the cvar doesn't exist or isn't used — `registered_in` and the raw corpus (`python tools/disasm_query.py cvar "^name$"`) still work; only the kind/default/help recovery failed. |

### Known gaps (read before trusting a row)

- **Not every cvar is a variable, and not every command is obviously a command.** The
  underlying `cvars` table is "string shaped like a cvar name" per
  `E:\kcd2_disasm\AGENTS.md` -- it includes some false friends (log-tag strings, format
  strings, etc. that merely look cvar-shaped). A `kind` of `unknown` is common for these;
  treat any single row with no `registered_in` hits at all as suspect.
- **`default` is frequently blank even for real cvars.** Many defaults are set from a
  variable, another cvar, or a platform branch rather than a compile-time literal --
  this generator only recovers literal-immediate defaults sitting directly at the
  call-site.
- **Multiple `registered_in` entries can mean duplicate registration OR one registration
  plus incidental string collisions in adjacent code** -- read the disasm yourself
  (`python tools/disasm_query.py cvar "^name$"`) before relying on a `medium`/`low` row.
- **RVAs and `sub_` names are only valid for build `release_1_5_1308617_856`.** Re-run after any corpus
  rebuild.
- Cross-reference counts (`vanilla_script_uses`, `mod_uses`, `notes_doc`) are simple
  whole-word text scans, not AST-aware -- a match means the literal identifier appears in
  that file, not necessarily that it's used as a cvar there.
- **The corpus's own `cvars` table only ever captures names starting with a lowercase
  letter** (confirmed empirically: 0 of its rows start uppercase on this build). A whole
  family of real, registered cvars whose name starts uppercase -- e.g.
  `WH_AI_CombatMove_TacticalSurround`, `WH_AI_CombatDirectionFactor` -- is registered by
  the exact same functions as ordinary `wh_ai_*` cvars but is invisible to that table. This
  generator recovers them with a second pass: any cvar/command-shaped string (any case)
  referenced by a function already trusted as a registrar is a candidate, kept only if it
  actually ties to a real registration call-site once re-parsed. These rows have
  `source` = `harvested (...)` instead of `corpus`; see `console-variables.md`'s TL;DR for
  the current count.

See `docs/kcd2/console-variables.md` for the curated, human-readable companion page, and
`docs/mercenaries/tech/disassembly.md` for how to query the corpus directly.
